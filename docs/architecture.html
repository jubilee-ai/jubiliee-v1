🔄 Training Job Dataflow

1
React UI sends training goal + dataset selection via HTTP POST to /api/train/stream
2
FastAPI creates a training_jobs row in Postgres, dispatches to Celery via Redis queue (or runs sync + streams SSE)
3
LangGraph Agent runs the pipeline: data collection → cleaning → feature engineering → label/split → train → evaluate. Each step calls OpenAI for tool-use decisions.
4
register_dataset() writes dataset metadata to Postgres datasets table (no files uploaded). Datasets loaded from Kaggle/HuggingFace/local CSV into memory.
5
register_model() UPSERTs into models + model_versions, then uploads .joblib weights to Cloudflare R2 via ArtifactStore (boto3 S3 API). The storage_key is saved in model_versions.
6
save_run_dataset_links() writes run_dataset_links rows connecting the training job to each dataset by role (source, train, validation, test) — enabling bidirectional queries.
7
Progress streams back to React UI via SSE. On completion, user can predict with the model — load_model() fetches weights from R2 if not cached locally.

⚡ Railway Services

  • FastAPI — HTTP API + SSE streaming
  • Celery Worker — async training execution
  • Redis — Celery broker + result backend
  • PostgreSQL — all persistent state

🗃 Postgres Tables

  • training_jobs — job status, progress, state
  • datasets — name, source_type, JSONB props
  • models — stable identity per model concept
  • model_versions — R2 key, metrics, version #
  • run_dataset_links — join table (role: source/train/val/test)
  • training_summaries — post-training chat context
  • agent_checkpoints — LangGraph HITL state
  • chat_threads — thread metadata

☁ Cloudflare R2

  • Bucket: jubilee-models
  • Stores: model weights (.joblib) only
  • Key format: models/{name}/v{n}/artifact.joblib
  • Access: boto3 S3-compatible API
  • Fallback: LocalArtifactStore for dev

✨ External APIs

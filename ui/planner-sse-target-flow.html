Target architecture: frontend → SSE → graph agent

Ideal end state from the graph migration plan: graph training SSE matches the rich node_complete shape; the client applies updates through one shared training-pipeline reducer so standalone and chat-bridged runs stay in sync; experiment-scoped context prevents patches from landing on the wrong session.

Target: POST /api/chat — body: linked_datasets, resume_training, … SSE: fetch + ReadableStream (not EventSource) HTTP intent: LLM (structured) + hard overrides Graph planner: structured Plan (not bind_tools)

Single public stream entry: clients use POST /api/chat only. Deprecated routes POST /api/train-graph / POST /api/train-graph-resume are thin wrappers for backward compatibility.

Two different “routers”: (1) HTTP intent router in backend/chat/intent_router.py — small LLM (e.g. CHAT_INTENT_ROUTER_MODEL=openai:gpt-5.4-mini) chooses training graph SSE vs orchestrator chat SSE when the user did not set mode or link datasets; hard overrides apply for linked_datasets, mode=train, mode=chat, and resume_training. (2) Graph internal planner inside LangGraph — LLM emits a validated Plan for step dispatch; that is not the HTTP router.

HTTP intent router (final target)

Hard rules
Evaluated first in backend/chat/service.py → should_route_to_training_graph(request).
  • resume_training set → graph resume stream (separate branch).
  • linked_datasets non-empty → training graph (user explicitly attached data).
  • mode: "train" → training graph.
  • mode: "chat" → orchestrator chat (skip LLM).
LLM
If none of the above forced a path, backend/chat/intent_router.py calls init_chat_model(CHAT_INTENT_ROUTER_MODEL).with_structured_output(IntentResult) with a short system policy: pipeline run vs Q&A. On missing OPENAI_API_KEY or model failure, default is orchestrator chat (safe; avoids accidental graph runs).
Downstream
True → training_service.generate_graph_sse_events(...). False → generate_chat_sse(...) (tokens, tools, optional train_model bridge).

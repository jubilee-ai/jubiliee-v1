LLM review → decision

Evaluator edges: continue → Dispatcher (next step), replan → Planner (new plan), amend → Dispatcher (modified remaining steps, mapped to "continue"), done → END. Built in agents/training/core/graph.py via StateGraph[TrainingAgentState].

Planner Node (core/planner.py)

  • Wrapped by run_with_hitl("planner", ...)
  • Formats PLANNER_PROMPT with goal, datasets, preference, state summary, replan context
  • Calls gpt-5.1 with structured output → Plan (steps + skipped + strategy)
  • _validate_plan() enforces constraints: data_collection first, generate_report last, training_approval before training, auto-inserts missing required steps
  • Clamps text: strategy ≤220 chars, rationale ≤90 chars, skip_rationale ≤150 chars
  • Produces: plan, plan_index: 0, plan_strategy, plan_history
agents/training/core/planner.py

Evaluator Node (core/evaluator.py)

  • Fast-path 1: completed step == generate_report → done (no LLM)
  • Fast-path 2: no remaining steps → done (no LLM)
  • Otherwise: formats EVALUATOR_PROMPT, calls gpt-5.1 → EvaluatorDecision
  • Decisions: continue, amend (modifies remaining plan), replan (back to planner), done
  • "amend" stores new plan but maps to evaluator_decision="continue" for routing
  • On "replan": appends current plan to plan_history
agents/training/core/evaluator.py

Dispatcher Node (core/dispatcher.py)

  • Pure routing — no LLM call, no HITL
  • Reads plan[plan_index], sets current_step to step name
  • If plan_index ≥ len(plan) → sets current_step = "done"
  • Conditional edge route_to_step() returns state["current_step"]
agents/training/core/dispatcher.py + edges.py

HITL: run_with_hitl() (core/hitl.py)

  • Wraps every step node (except dispatcher, evaluator)
  • Calls work_fn(state, feedback) → sanitizes via make_serializable()
  • Calls get_summary_fn(result) for the review card
  • Extracts state_snapshot (only STATE_SNAPSHOT_KEYS: 18 fields)
  • interrupt({node, summary, message, state_snapshot}) — pauses graph
  • parse_decision(): bool, "yes"/"ok"/etc → approved; other string → feedback; dict → {approved, feedback}
  • If rejected: loops back to work_fn with feedback
agents/training/core/hitl.py

3 Pipeline Steps (9 nodes, all HITL-gated)

data_collection
Load or retrieve dataset(s)
Linked → local retrieval agent → optional external (Kaggle/HF). Scores & picks best. No LLM.
select_model
Choose model family
supervised / unsupervised / neural_networks. Explicit pref skips LLM. gpt-5.1 structured output.
cleaning
Clean & standardize data
Delegates to run_cleaning_simple(). Target-aware if target column inferred.
label_split_definition
Target column + train/val/test splits
Delegates to run_label_split_definition(). Random/time/entity split.
feature_selection_specification
Analyze data & specify features
Delegates to run_feature_engineering_simple(). Produces FeatureSpec. Resets redo state.
feature_engineering_executor
Apply feature transformations
Delegates to execute_feature_spec_split(). Validates results.
training_approval
Propose config (HITL gate)
Manual interrupt() loop (not run_with_hitl). LLM proposes hyperparameters.
training
Train model + evaluate metrics
Delegates to _run_training(). May request feature redo.
generate_report
Save final training report
Builds report dict, writes JSON. No LLM. Evaluator fast-paths to "done" after.

All steps defined in agents/training/steps/orchestrator.py, delegating to impl files in agents/training/steps/. Constraint order enforced by planner's _validate_plan(): data_collection → ... → generate_report (last). Required steps (never skipped): data_collection, training, generate_report.

4 Linked Dataset Resolution

resolve_linked_dataset(entry) — 4-strategy resolver

Called in every SSE generator before the graph/agent runs. Tries strategies in order; returns registered ref name or None.

#StrategyWhen it matches
1get_registered_dataset(entry)Already in the in-memory registry (e.g. from a prior step)
2load_and_register_dataset(entry)Entry is a real file path under datasets_dir (csv/foo.csv)
3DB name lookup (case-insensitive) → properties["file"] → loadEntry is a display name like "Health Insurance Charges Dataset"
4DB UUID lookup → properties["file"] → loadEntry is a UUID string
backend/training/service.py · resolve_linked_dataset()

UI guard: ChatPanel.handleDatasetSelect

  • Checks dataset.trainable !== false — rejects explicitly non-trainable datasets
  • Key = dataset.file || dataset.id — never sends display name alone
  • If neither file nor id exists → skips with console.warn
ui/src/components/ChatPanel.tsx

Catalog: _dataset_to_dict (DB rows)

  • file = props.get("file") or None — no fallback to row.name
  • trainable = bool(file_path) — True only when a real path exists
  • JSON catalog fallback unaffected (those entries already have real paths)
backend/catalog/repository.py

When resolution fails, the SSE generator emits dataset_error. When ALL entries fail, final_linked = None (not the raw strings). Downstream data_collection falls through to the retrieval agent instead of silently looping.

7 Deduplication: stream_step_key

Backend: _pipeline_emit_key()

Format: {len(plan_history)}:{plan_index}:{node_name}
After a replan, plan_history grows, so the same data_collection gets a different key (e.g. "0:0:data_collection" vs "1:0:data_collection"). This allows the second execution to emit a new node_complete SSE event.

backend/training/service.py

UI: emittedStepsRef

Set<string> ref. On node_complete: checks event.stream_step_key ?? event.node. If already in set → skip. On node_skipped: key is "skipped:" + node. Cleared on every new startAgentStreaming, sendMessage (with datasets), and training_started.

10 Graph SSE Generators (detailed flow)

generate_graph_sse_events(goal, linked_datasets, model_pref, thread_id?, experiment_id?)

Primary SSE generator for the agentic graph pipeline.

  • 1. Generate or use provided thread_id (prefix: graph-)
  • 2. If experiment_id: update experiment's training_state.graph_thread_id
  • 3. Resolve linked_datasets via resolve_linked_dataset() per entry:
    • Success → emit dataset_loaded
    • Failure → emit dataset_error
    final_linked = registered_refs or None
  • 4. Create agent (MemorySaver checkpointer), initial state, store in repository
  • 5. Emit started (node="planner", progress=0)
  • 6. Delegate to _iter_graph_sse_lines() (see below)
  • 7. If interrupted: return (no completed event)
  • 8. Otherwise: save training context + dataset links, emit completed
  • Exception: emit error
backend/training/service.py

_iter_graph_sse_lines(agent, config, thread_id, stream_input)

Inner loop shared by both start and resume generators. Streams with stream_mode=["updates", "custom"].

  • Custom events: forwarded as type: "thinking" SSE with phase and message
  • __interrupt__: extracts interrupt info, snapshots state, emits interrupt SSE, sets _graph_sse_interrupted flag, returns (terminates generator)
  • Pipeline step nodes: deduped by _pipeline_emit_key(). Emits build_node_update() with stream_step_key
  • Non-pipeline nodes (planner, dispatcher, evaluator): always emitted via build_node_update()
  • Planner node: additionally emits node_skipped for each skipped step (deduped)
backend/training/service.py

generate_graph_resume_sse_events(thread_id, approved, feedback)

Resumes the graph after HITL interrupt.

  • Looks up agent from repository store by thread_id
  • Builds Command(resume=resume_value). If multiple interrupts: maps each interrupt id to the same decision dict
  • Delegates to same _iter_graph_sse_lines()
  • Same post-loop logic (check interrupted flag, save context, emit completed/error)
backend/training/service.py

11 Chat Orchestrator SSE (non-training path)

generate_chat_sse(thread_id, message, training_context?, experiment_id?)

Orchestrator agent stream for Q&A, analysis, and tool-based interactions. Uses stream_mode=["messages", "updates"].

  • Messages stream: yields token events (incremental LLM text) and tool_call events (deduplicated via _stable_tool_call_id())
  • Updates stream: yields tool_result events (content truncated to 2000 chars). If tool is train_model: yields retroactive step events via _emit_training_step_events()
  • Bookends: start at beginning, end at end
  • Persistence: saves accumulated response to experiment's chat_history
  • Training context: if provided, prepends a [SYSTEM CONTEXT ... END CONTEXT] block to the user message so the LLM can answer questions about prior training results
backend/chat/service.py
